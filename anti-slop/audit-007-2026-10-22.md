# Anti-slop audit 007

Date: 2026-10-22  
Scope: Facebook update source fallback  
Mode: after

## Finding

1. **The Facebook scan hard-stops without a Page access token** — Medium

   `/api/admin/facebook-scan` currently returns a 503 before attempting the configured public Facebook URL. That makes the requested second source unavailable even when the public page itself can be fetched.

   A public-page fallback is technically possible, but Facebook may serve a login shell, block/interstitial, or HTML that contains only page metadata instead of post bodies. The fallback therefore must parse only verifiable server-rendered or embedded post records, report its source and limitations, and never treat missing content as a successful update.

   **Proposed fix:** keep the Graph API/Page token path preferred; add a bounded public-page fallback that tries the configured page and posts URL, parses only verifiable public post records, caches the last successful result, and exposes a source/warning in the admin review UI. Keep the existing review/apply-to-draft flow; do not auto-publish scraped content.

## Approval gate

No product code or deployment was changed by this audit. Approve finding `1` to enable the public-page fallback as the second Facebook source.

## Resolution

Finding `1` was approved on 2026-10-23. Implemented only the approved fallback:

- Graph API/Page token remains the preferred source.
- The Worker now tries the configured public Page, `/posts`, and timeline HTML when a token is absent or the Graph request fails.
- HTML is fetched with a timeout and a 1.5 MB response cap; only post-like records with verifiable post markers are normalized.
- The last usable result remains available when Facebook returns a shell, block, timeout, or other unreadable response.
- Admin now labels the source (`Page Graph API`, `public Page HTML`, or saved result) and shows warnings.
- The existing review and apply-to-draft flow remains; nothing is auto-published.
